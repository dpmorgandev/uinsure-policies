# inv-001: F2 attempt-3 escalation
## Question
Why does the reviewer FAIL build/F2 at attempt 2, and is each cause in the code, the tests, or the orchestrator's briefs?
## Hypothesis
Both F2 FAILs share one cause: canned response values survived because nothing told them apart from real
ones. At the stub, canned status and currentTermNumber matched the expected values. At green, hasClaims
stayed canned because the orchestrator's t2/t8 briefs said it stays until F3, and no t1 test varies it.
Disproved if hasClaims had no stored source at the reviewed head, or a test seeds hasClaims true.
## Evidence
- docs/trace/build/F2/verdicts/A2-reviewer.json: FAIL, R1 P1 (hasClaims) and R2–R6 P2
- docs/trace/build/F2/verdicts/A2-security.json: PASS, P2 note on the cancellationToken query key
- docs/trace/build/F2/findings/A1.md: attempt 1's stub-gate FAIL, canned status and term number
- docs/trace/build/F2/findings/A2.md: this investigation's diagnosis, I1–I6
- docs/trace/build/F2/loop.jsonl: A1's route fixed two constants and did not dispatch the tester; t6's
  gate.green receipt records the Services not-found gap as "noted, not closed"
- The orchestrator's t8 dispatch brief (session record; dispatch prompts are not in the trace): it said
  "hasClaims false, refunds/claims empty and cancellation null stay until F3 (no data yet)". The t2 brief
  said the same of the canned members. The investigator could not see either prompt and left the brief leg
  unverified; this line supplies it.
## Findings
**Yes, the hypothesis holds for R1 and A1. It does not explain R2–R6.** Each cause is classified in
[findings/A2.md](../../trace/build/F2/findings/A2.md):
- I1 (R1) · tests, enabled by the brief: `PolicyMappings.cs:37` passes a literal false although
  `Policy.HasClaims` is stored and restored; `PolicyResponseAssert.cs:47` only expects false and the test
  `PolicyBuilder` cannot seed true. The orchestrator's brief told the builder hasClaims has no data yet,
  which was false. Same class as A1 (a canned value that equals every expected value) on a new field.
- I2 (R2) · code: `PolicyResponse.cs:3-4` still calls status and currentTermNumber canned; written at the
  stub, never re-read at green or refactor. New.
- I3 (R3) · code: `TwoDecimalPlacesConverter.cs:17` writes "F2", which rounds as well as pads, and it is
  the only code in `src/` that rounds money. The echo-text change is evidenced only by gate.run. New.
- I4 (R4 + security P2) · code: `RejectUnknownQueryParametersFilter.cs:11` counts route, body and special
  parameters as known query keys. New.
- I5 (R5) · tests: the unpaid-second-term row asserts no status. This is the gap A1's I2 named, left open
  because A1's route was code-only.
- I6 (R6) · tests, carried by an orchestrator decision: no Services test for the not-found result; the
  orchestrator noted the gap at t6 and did not close it.
Common thread: three causes trace to the orchestrator (the hasClaims brief, the code-only A1 route, the
gap left open at t6); the tests then had nothing that could fail.

  formatting slip into an outage; writing it exactly lets a test catch it with no runtime failure.
