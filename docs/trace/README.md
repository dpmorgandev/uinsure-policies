# How to read the trails

Written by David and the main session in F0a. Everything else under `docs/trace/` is generated or
recorded, and says so in its first line.

## What's here

```text
docs/trace/
  README.md                  this file (written)
  requirements-matrix.md     generated: every rule in docs/requirements.md → node, tests, red/green/refactor commits, QA step, sign-off, PR
  <plan>/<node>/
    README.md                generated: the node summary; start here
    walkthrough.md           generated: every commit in order, one line each
    activity.jsonl           generated by a hook: who touched which file, with which tool
    loop.jsonl               generated by the orchestrator: every state change and gate result, with the command and its exit code
    verdicts/<round>-<agent>.json   recorded: each reviewer and security verdict, after its schema check
    findings/<round>.md      recorded: the investigator's diagnosis for each FAIL (A<n>) or David steer (D<n>)
```

**Generated** means a hook or `.claude/scripts/render-trace.mjs` wrote it, never an agent producing the
code. **Recorded** means a hook stored an agent's judgement verbatim. The trail doesn't vouch for it, but
it can't be altered by the agent afterwards. **Written** files (this one, the QA scripts, David's PR
paragraph, `docs/lessons.md`) are labelled as such.

## Reading a node

1. **`README.md` → Completeness.** The first section is always `OK` or `TRAIL INCOMPLETE: <reasons>`.
   An incomplete trail is never shown as clean.
2. **Rules:** each rule's tests, its red commit, its green commit, and its QA step.
3. **`walkthrough.md`:** the TDD order commit by commit (red → stub → domain → services → persistence →
   api → refactor). The "what it did" column is the commit subject, in the agent's words.
4. **Loop:** each attempt and its verdicts. A FAIL links to its findings file, and the next attempt's
   commits carry `Fixes-Finding:`.
5. **Who touched what:** each commit's `Agent:` trailer next to the agent the hook saw make it.

## Re-verifying with git alone

The trailers make every claim checkable without the trail files:

```sh
git log --format='%h %(trailers:key=Agent,valueonly,separator=%x2C) %(trailers:key=TDD,valueonly,separator=%x2C) %(trailers:key=Rule,valueonly,separator=%x2C) %s' origin/main..<branch>
git log --first-parent main          # one merge per feature
```

The merge commits keep every TDD commit and its SHA on `main`.

## F0a

F0a built the harness in-session, before the hooks existed. It has no hook receipts: it's witnessed by
git and trailers only, and its check reports `OK (git-only, F0a)`. Its spike and tool receipts are in
`build/F0a/`. F0b is the first fully witnessed node.
